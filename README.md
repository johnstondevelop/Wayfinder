# LovinglyLost

LovinglyLost is a romantic road-trip planner. You give it a starting point, one or more stops along the way, and how many days you want the trip to take, and it plans a driving route between everything, splits the drive time evenly across your days, and if you'd like it goes looking for scenic and romantic spots near your route, like viewpoints, waterfalls, wineries, and little gardens, so you can build in some detours worth stopping for. Everything shows up on a map, and every stop you tap gives you links out to Google Maps and Apple Maps so you can get walking directions or save it for later.

There's no backend and no build process behind any of this. It's a plain website a page of HTML, a stylesheet, and a handful of JavaScript files that runs entirely in your browser and talks directly to Mapbox's mapping and location services. That keeps things simple to run and easy to read through, at the cost of putting a bit more responsibility on the browser itself, which is worth keeping in mind as the app grows.

Because the app's JavaScript is loaded in pieces (as ES modules) rather than as one bundled file, browsers won't run it if you just double-click index.html and open it directly. It needs to be served over a local web address instead. The simplest way to do that, if you have Python installed, is to open a terminal in the project folder and start Python's built-in web server, then open the page through the local address that gives you. Any other simple static file server works just as well.

All of the things you'd actually want to tune your Mapbox access token, where the map starts before you've planned anything, which categories of place count as "romantic" for the scenic-stop search, and how far a place is allowed to be from your route before it's considered too far out of the way live together in one settings file inside the Maptoken-categories folder, called maptoken-config.js. That's the one place to look if you ever need to swap in a different Mapbox token or adjust those defaults.

For how the actual code is organized — what each file does and how they work together see the README inside the Maptoken-categories folder. And for anything to do with the Google Maps and Apple Maps links on each stop, or the question of whether real photos of these places could be added someday, see the separate maps-and-photos notes at the project root.

A couple of things worth knowing about how the app behaves today: locations only get resolved to map coordinates once you leave the text field, either by clicking one of the autocomplete suggestions or by clicking or tabbing away from it, and that resolution happens in the background over the network. If you type a location and click "Find our route" immediately afterward, without pausing on a suggestion first, it's possible for the click to land before that background lookup finishes, in which case the app will tell you it still needs a starting point and a stop even though you just typed one in. Clicking a suggestion from the dropdown avoids this, since that fills in the coordinates right away. It's also worth knowing that the scenic-stop search can be quite chatty with Mapbox — it searches near several points along your route, once per category you have selected — so a long route with every category turned on can mean dozens of requests in a short window, and if Mapbox starts rate-limiting those requests, the app will let you know that some stretches of the route may be missing results because of it, rather than failing silently.
